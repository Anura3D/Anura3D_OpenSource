This document provides a complete summary of the implementation that makes the 
APIC/FLIP blend factor fully user-controllable in Anura3D through:

1. CPS file input (manual text editing)
2. GiD GUI interface (visual editor)

Both methods write to the same CPS parameter and are read by the same Fortran 
code, ensuring consistency regardless of how users input the value.

USER INPUT (GiD GUI)

    │
    ├──→ Value stored in XML tree as:
    │    <value n="APIC_FLIP_blend_factor" v="0.95">
    │
    ↓
TCL PROCESSING (createCPS.tcl)
    │
    ├──→ XPath query extracts value from XML tree
    ├──→ {string(container[@n="Calculation_Data"]/value[@n="APIC_FLIP_blend_factor"]/@v)}
    │
    ↓
CPS FILE GENERATION
    │
    ├──→ TCL writes to .CPS file:
    │    $$APIC_FLIP_BLEND_FACTOR
    │    0.95
    │
    ↓
FORTRAN READING (ReadCalculationData.FOR)
    │
    ├──→ Reads keyword $$APIC_FLIP_BLEND_FACTOR
    ├──→ Reads numeric value (0.95)
    ├──→ Validates: 0.0 ≤ value ≤ 1.0
    ├──→ Stores: CalParams%APIFLIPBlendFactor = 0.95
    │
    ↓
RUNTIME USAGE (MPMDYNConvPhase.FOR)
    │
    ├──→ alpha = CalParams%APIFLIPBlendFactor
    ├──→ v_new = alpha × v_APIC + (1-alpha) × v_FLIP
    │
    ↓
SIMULATION RESULT
    │
    └──→ Particle velocities updated with 95% APIC, 5% FLIP

Problem: Fortran error reading parameter
  → Verify CPS file format (keyword, then value on next line)
  → Check value is numeric (not text)
  → Ensure Fortran code is recompiled

Problem: Simulation results unchanged
  → Verify parameter is actually being read (add debug output)
  → Try extreme values (0.0 or 1.0) to see clear difference
  → Check you're running updated executable
